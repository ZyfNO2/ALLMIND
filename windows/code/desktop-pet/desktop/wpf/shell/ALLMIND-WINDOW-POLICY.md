# ALLMIND 桌宠窗口策略（开发版）

这是 GPT-Niang 的独立 ALLMIND 模式增量。原 Codex 跟随模式保留；本文件不表示已有安装包或完成真实全屏验收。

## 使用

在右键菜单的“悬浮与显示”中选择：

- **智能悬浮**：普通应用上方显示，同屏确认全屏后收起。
- **常驻悬浮**：保留置顶；独占全屏下是否可见由 Windows/游戏决定。
- **普通窗口层级**：不置顶，允许被其他窗口遮挡。

新安装默认智能悬浮；已有置顶/普通层级偏好会保留。拖动、按压和右键入口继续使用原生实现，不新增闲置浮动、悬停工具栏或单击打开聊天。

关闭桌宠窗口/Alt+F4 会收起到通知区。手动收起会保存，退出全屏或解锁不会擅自唤回。通知区“显示桌宠”、重复启动以及唤出热键可恢复；右键“退出 ALLMIND”才会停止本产品后台。默认热键 Ctrl+Alt+P 被占用时不抢占，可在同一子菜单改为 Ctrl+Alt+Shift+P 或关闭。

全屏期间显式唤回最多显示 10 秒，只作用于当前同一外部窗口；它不能越过锁屏、挂起或 Windows 演示模式。通知区/热键等显式恢复会同时关闭完全穿透，让角色重新可拖动和右键；自动退出全屏不会改变穿透偏好。

## 后台与隐私边界

自动收起不会退出 ALLMIND 后台，也不会取消用户已经发起的聊天/Wiki 请求。结果保存在原角色/会话，恢复时不自动重发或补弹。免打扰的用户配置不会被自动策略改写。

不可显示时会停止角色显示调度、主动气泡/音效和音乐律动采集。音乐启用意图与运行状态分开，恢复只重开仍被用户启用的律动；如果用户已关闭则保持关闭。静态角色不额外建立高帧率循环。

前台采样仅读取窗口属性、边界、显示器及会话/通知状态，不读取键盘正文、窗口标题或屏幕内容，不调用模型判断场景。

## 开发与诊断

先用 Windows PowerShell 5.1 运行 `runtime/build-allmind-host.ps1` 构建宿主。在已构建的 ALLMIND 核心目录运行：

```text
node desktop/wpf/main.mjs --data <隔离数据目录> --shell-root <本目录的绝对路径>
```

控制器默认从 `dist/` 启动同一份 ALLMIND 后台。当前仍是两个开发树联调，不是可复制的安装包；不能直接分发依赖开发机路径的启动脚本或 node_modules junction。

宿主偏好和诊断位于数据目录的 `host/`：

- `visibility.json`：显示模式、手动收起、穿透、热键与回复提醒偏好。
- `visibility-state.json`：实际显示结果、原因、采样/热键错误、律动运行状态，不含聊天正文或凭据。
- `visibility-error.log`：窗口策略异常；`appearance-error.log` / `host-sync-error.log`：形象及宿主同步错误。

诊断中的 `requestedVisible` 只代表恢复意图被接收，`effectiveVisible` / `visibility.visible` 才代表窗口实际结果。锁屏或演示阻断时可以接收恢复意图，但不会谎报已经显示。

检测失败会明确降级：可用会话下转普通层级并抑制自动提醒；会话未知时先不展示私人内容。正常采样恢复后重新评估。管道彻底断开时停止主动提醒，需重新启动宿主；不会自动重新发送未知状态的模型请求。

## 测试边界

`tests/allmind-visibility.test.ps1` 测纯策略/偏好/几何；`tests/allmind-observer.test.ps1` 测真实 Win32 热键冲突/换绑/释放；`tests/allmind-music-suspend.test.ps1` 使用隔离的 WPF 组件验证真实音频线程和定时器释放；`tests/allmind-notifications.test.ps1` 测恢复后的旧通知抑制。四项均加入 Windows 测试入口，组件测试不冒充真实桌面输入。

真实浏览器 F11、游戏独占/无边框全屏、混合 DPI、多屏、锁屏、睡眠及通知区操作仍需要原生行为验证。前台检测不能保证覆盖失去前台的副屏播放器、特殊游戏 overlay 或所有远程/虚拟桌面场景。UI 视觉验收另行进行。
