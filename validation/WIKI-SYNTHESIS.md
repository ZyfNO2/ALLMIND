# AI Wiki 编纂合同

入口：管理页「记忆 → 日常整理」。先确认角色知情范围，准备材料，允许本次外发，再生成草稿。核对段落、原文、关系与未采用资料后明确应用。此手动授权不启用自动记忆。

应用内嵌规则改造自 [Karpathy LLM Wiki 工作流](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f) 与 [GoogleCloudPlatform Open Knowledge Format v0.2](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/ad30107c31c06aec8a7d5636e0d1058118604e6f/SPEC.md) 及其 [参考编纂提示](https://github.com/GoogleCloudPlatform/open-knowledge-format/blob/ad30107c31c06aec8a7d5636e0d1058118604e6f/src/reference_agent/prompts/web_ingestion_instruction.md)。保留原件、跨资料综合、引用、域隔离与维护原则；不是照抄网页提示，也不声称本项目JSON是官方OKF文件格式。

`memory/wiki-synthesis-protocol.ts` 是完整提示与 JSON Schema 的事实源。模型最终只返回 `allmind-wiki/v1` JSON：

- `inputHash`：原样回显任务输入指纹。
- `pages`：稳定页面ID、标题、资料域、综合段落；每段附材料ID和逐字连续原文。
- `relations`：有向语义关系、标签与两端依据。来源引用由应用生成，不冒充人物关系。
- `coverage`：每条输入恰好一次，列实际引用页面；未采用须说明原因。

任务包包含 `PROMPT.md`、`materials.json`、`response.schema.json`、stdlib-only `validate.py` 与应用生成的文件哈希清单。GPT网页收到该包及完整规则，要求自行运行检查和修正；无工具时不能声称已运行。产品收到结果后仍独立校验同一结构、原文、资料域、关系端点及覆盖清单。合法引用不等于语义正确，需审核。

网页编纂要求独立页面来源，在提交前核实唯一的High标签及任务包上传完成；不可核验就拒绝发送，不静默用Medium。API默认不附加effort；只有用户确认服务支持并显式配置 `reasoningEffort` 后发送 `reasoning_effort`，失败不删除参数自动重试。普通API无需执行Python或创建ZIP，也不能假装已经运行脚本。

材料按当前角色/用户配对和知情范围筛选；不允许用空视图发送带边界资料。原作、私设、模拟、真实记录和外部资料分域，页面引用不同域会拒绝。派生页面继承依据中的最严格章节，来源修改后失效，撤销/删除依据时清理派生正文。固定原始人格/条目不被编纂覆盖；用户手改派生页会阻止覆盖。

任务准备与模型生成不改Book。应用以原始Book版本、配置版本、输入指纹和明确确认保护；重复生成请求不会重发，重复提交返回原回执。中断任务保留状态，重启不自动生成。输入超预算明确失败，不截断材料。新资料需显式准备新任务；模型按已有页面ID进行增量提案，未返回的旧页不自动删除。

网页中断后可明确选择「接续读取原网页结果」，只读取原请求回执，不再次发送。手动 High 编纂的完成回执保存在本机并可跨后台重启接续；删除或撤销依据时，关联草稿正文和已完成网页缓存同步清除。生成中的任务重启后标记为未确认完成，不能自动重发。

本说明是实现行为，不是实时验收证书。fixture、真实API、真实网页、自检执行、应用/召回/重启结果须分别记录。

当前状态以 `release-status.json` 顶部 `currentSummary` 为准，其余带日期字段保留当时证据。历史网页 High 的小规模实体／事件／主题编纂、应用、召回及重启已有通过记录；真实 API 普通聊天成功不能替代严格 Wiki 编纂验收，之前的 API 结构／覆盖／截断失败保持失败。2026-10-22 新增的 JSON Schema / JSON 对象 / 仅提示词模式和多批检查点通过受控服务验证。真实 Minimax M3.1 Flash Free 在四条不变合成资料上，第一份结构通过但语义不合格，第二份引用与端点不合格，均未应用；明确修正后第三份生成 5 页（4 实体、1 事件）和 6 条有据关系，经 Codex 独立语义审核、产品应用、真实预设召回“林澄”和重启回放通过。四次真实模型调用包含三次生成尝试和一次召回；没有自动重试，不代表任意材料或任意模型一次成功。旧日期 API 失败仍保留。

API 的 `structuredOutput` 是显式配置：默认 `json-object`；`json-schema` 使用严格响应格式（需服务实际支持）；`prompt` 不发送格式参数。选择严格模式会将 schema 对象属性统一列为 required；返回后仍运行产品原有 schema 与逐字引用、域及 coverage 校验，不修复模型生成的缺失类型或伪造引用。服务拒绝参数时不自动改模式或重发。可先用少量合成材料验证所选模型，再决定是否发送个人资料。

普通 Markdown/TXT 导入采用独立预览入口，最长 1 MiB，超长正文按顺序完整分段。资料域仅允许外部资料、作者自设或模拟资料；不自动成为核心人设，也不能通过文件导入把虚构记录标为真实共同经历。确认保存后才作为编纂材料。
